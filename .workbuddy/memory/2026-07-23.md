### 核心思路调整（用户反馈）

旧版 Manager/ 的处理方式是「跨主版本 → 拒绝，请手动下载」—— **被动、不友好**。

## v3.01.03 修复（用户反馈：升级后启动的是旧版）

### 根因（用户问「为什么不是这个」）

**旧版 Manager/bds_manager.py:7341** 的重启逻辑写死了文件名：

```python
def _restart_app(self):
    self.save_config()
    subprocess.Popen([sys.executable, os.path.join(SCRIPT_DIR, "bds_manager.py")], ...)  # ← 写死
    QApplication.quit()
```

升级流程：
1. 旧版 v2.1.2.00 启动 → 下载新版 v3.01.02 → 解压（main.py / pages/ / backend/ 全部就位）
2. `self.parent._restart_app()` → `subprocess.Popen(["python", "bds_manager.py"])` ← 写死！
3. 启动的还是旧版 `bds_manager.py`，UI 看起来还是旧的
4. **run.bat 已被覆盖为 `python main.py`，但当前进程用的是旧版的 subprocess.Popen**

### 修复（无需改旧版代码）

新版 `InstallUpdateWorker` 解压后**自动把 `bds_manager.py` 覆盖为一个转发 stub**：

```python
# -*- coding: utf-8 -*-
# 由新版安装器自动生成，转发到 main.py（已废弃 v2.x 单文件架构）
import os, sys
_SD = os.path.dirname(os.path.abspath(__file__))
os.chdir(_SD)
sys.path.insert(0, _SD)
import main  # 触发 main.py 执行
```

未来任何旧版 `subprocess.Popen('bds_manager.py')` 都会通过 stub 自动转发到 main.py。


### 关键 Bug 与修复

#### RLock 重入死锁（最关键）
- **症状**：`_Store.add()` 死锁挂起（任何 notify() 调用都卡）
- **根因**：`add()` 用 `threading.Lock()`，内部又调用 `_load()`（也要同一把锁），普通 Lock 不可重入 → 同一线程死锁
- **修复**：改为 `threading.RLock()`（可重入锁）
- **教训**：当一个加锁方法调用另一个也加锁的方法时，**必须用 RLock**，否则运行时挂死

#### notify 跨线程
- 设计上 `notify()` 任何线程可调（Worker 也会触发备份完成通知）
- 通过 Qt 的 `Signal` 自动 QueuedConnection 跨线程安全
- 用 `try/except RuntimeError` 兜底 QApplication 未初始化场景

### 关键设计决策回顾
1. **RLock 必用**：`add()` 内调 `_load()` 必须用 RLock，否则死锁
2. **Toast 与通知并存**：通知中心是「补充」而非「替代」Toast

### 教训
- **加锁方法调加锁方法 → 必须 RLock**：任何"在锁内调别的加锁方法"的场景都要警觉
- **QObject 创建不需要 QApplication**：可以安全创建 Signal 承载的 QObject
- **fixture 模拟主窗口时要用 QWidget 子类**：`QApplication.activeWindow()` 不可靠，自己 mock 一个最稳
- **PySide6 旧版 Lock 不重入**：所有需要重入的场景必须显式用 RLock

```python
self._show_anim = QPropertyAnimation(...)  # 保持引用
```

## 20:44：抽屉 mask 事件冒泡 bug（用户反馈）

### 用户反馈
> 为什么消息栏这些消息点一下这个界面直接消失了，都没有像之前的展开。

### 根因
上一轮加的"点 mask 关闭抽屉"机制有个副作用：
- mask 是 main window 的子 QWidget，覆盖整个主窗口区（除 drawer 外）
- mask.mousePressEvent = lambda _e: self.hide_drawer()
- 用户点 NotificationItemWidget（QFrame 子控件）时，事件先给 QFrame 处理
- QFrame.mousePressEvent 默认**不 accept**，事件冒泡到 parent（list_container → drawer → main window）
- 但 main window 也没有 accept → 事件继续向上 → 最终到 mask 触发 hide_drawer()！
- 结果：单击通知 → 抽屉直接关闭，连展开都没机会执行

### 修复（2 处）
1. **NotificationItemWidget.mousePressEvent / mouseDoubleClickEvent 末尾加 `event.accept()`**
   - 阻止事件冒泡到外层 mask
   - QPushButton 类型的 chip/按钮本来就 accept，这里是 QFrame 缺这步
2. **NotificationDrawer 自己也 override mousePressEvent：`event.accept()`**
   - 防止点击 chip 行下方空白处时事件冒泡到 mask
   - drawer 的子控件（chip、按钮、通知项）本身已 accept，这里兜底空白区域

### 验证

```python
#   QFrame.mousePressEvent → event.accept() ✓ 消费
#   事件停止传播，不冒泡到 mask
#   → 单击切换 _expanded 状态 ✓
#   → 双击触发 navigate + hide_drawer ✓
```

### 教训（关键！必须记住）
1. **mask/overlay 类 widget 拦截事件是双刃剑**：它能解决"点外部关闭"，但也会吃掉子控件的事件冒泡
2. **所有子控件必须 accept 事件**：QPushButton/QLineEdit 默认 accept，但 QFrame/QWidget 默认不 accept——加 override 时一定要 `event.accept()`
3. **容器自己也加 accept 兜底**：空白区域（chip 行下方、列表上方）事件也会冒泡，容器 override `event.accept()` 兜住
4. **测试场景要覆盖"事件冒泡路径"**：不能用 `click()` 模拟（PySide6 的 click() 直接派发到目标控件），要真用 `QTest.mouseClick()` 在屏幕坐标点击才能暴露冒泡 bug

## 20:51：mask 方案根本性修复（用户反馈"无论左键右键单击都直接退出了"）

### 用户反馈（20:45）
> 我无论怎么左键右键单击。他都直接退出了。都没有展开。

### 根因（深层）
之前的 mask 方案有两层问题：
1. **`QWidget::mousePressEvent` 默认实现会调 `event->ignore()`**（不是 accept！）
2. 子控件不显式 accept，事件会**冒泡**到 parent → drawer → main window → mask
3. mask 拦截到任何 mousePressEvent 就调 `hide_drawer()`
4. 结果：单击/右键单击通知项 → 事件冒泡到 mask → 抽屉被关

之前的"加 `event.accept()`"修复其实是无效的——QFrame 内部用 super().mousePressEvent() 时调到了基类的 ignore 实现。

### 真正的修复方案：改用 eventFilter
```python
def eventFilter(self, obj, event):
    if (self._is_installed and obj is self.parent()
            and event.type() == QEvent.Type.MouseButtonPress):
        try:
            click_pos = event.position().toPoint()
        except Exception:
            click_pos = event.pos()
        drawer_topleft = self.mapTo(self.parent(), QPoint(0, 0))
        drawer_rect = QRect(drawer_topleft, self.size())
        if not drawer_rect.contains(click_pos):
            # 点 drawer 外 → 异步关闭（避免在 eventFilter 中销毁自己）
            QTimer.singleShot(0, self.hide_drawer)
    return super().eventFilter(obj, event)
```

**核心思路**：
- 不在 drawer 子控件层挡事件，而是在**主窗口层**拦截
- 按点击位置判断是不是在 drawer 矩形内 → 决定要不要关闭
- drawer 子控件的事件冒泡路径完全不受影响（不再有 mask 拦截）
- `eventFilter` 返回 `super().eventFilter(...)` 不消费事件，让事件继续传给原本的目标

### show_drawer / hide_drawer 配套
```python
def show_drawer(self):
    ...
    if not self._is_installed:
        parent.installEventFilter(self)
        self._is_installed = True

def hide_drawer(self):
    if getattr(self, "_is_installed", False) and self.parent() is not None:
        self.parent().removeEventFilter(self)
        self._is_installed = False
    ...
```

### 教训（重要！更新之前的认知）
1. **PySide6 `QWidget::mousePressEvent` 默认调 `event->ignore()`**——这与 Qt 文档说法一致（默认 ignore）
2. **`event.accept()` 必须显式调用才会阻止事件冒泡**——之前我对"override mousePressEvent + accept 阻止冒泡"的认知是错的
3. **mask widget 方案在 PySide6 中不可靠**：因为它依赖冒泡，而冒泡路径上各层都可能意外 ignore
4. **eventFilter + 几何判断是更专业的遮罩实现**：在主窗口层拦截，按 hit geometry 精确判断
5. **`QApplication.sendEvent(widget, event)` 不走 hit test**：要模拟真实点击必须用 `QTest.mouseClick(win, ..., pos)`（但即使 QTest 也只命中直接子，跨多个嵌套 child 时仍需手动 sendEvent 到目标 widget）
6. **`QTimer.singleShot(0, hide_drawer)` 防止 eventFilter 中销毁自己**：在事件处理过程中调用可能影响栈帧

修复：用 Qt 标准的 `saveGeometry()` + `restoreGeometry()`：

```python
def _save_geometry(self):
    geom_b64 = bytes(self.saveGeometry().toBase64()).decode("ascii")
    config_mgr.set("window_geometry", geom_b64)

def _restore_window_state(self):
    geom_b64 = config_mgr.get("window_geometry", "")
    if geom_b64:
        ba = QByteArray.fromBase64(geom_b64.encode("ascii"))
        if not ba.isEmpty() and self.restoreGeometry(ba):
            return  # 还原成功（含 maximized / fullscreen / normal）
    # fallback（旧 config 或首次启动）
    self.resize(config_mgr.get("window_width", 1200),
                config_mgr.get("window_height", 800))
```

**saveGeometry 的关键特性**：
- 内部永远保存 `normalGeometry`（最大化前的实际尺寸）+ `windowState` flag
- 即使你调用 saveGeometry 时窗口处于最大化状态，保存的也是 normal geometry + maximized flag
- restoreGeometry 能完整还原 3 种状态：普通 / 最大化 / 全屏

### 触发时机
- `resizeEvent` → 实时保存（用户拖动窗口时）
- `closeEvent` → 关闭前最终保存
- `_restore_window_state` → 启动时还原

### 根因（PySide6 6.x 的关键差异）
- `Qt.Key` 是 `IntEnum`（int 的子类）→ 可以直接做位运算
- `Qt.KeyboardModifier` 是 `Flag`（**不是 IntFlag**）→ `int()` 会失败
- `event.modifiers() | event.key()` 在 PySide6 中返回 `KeyboardModifier` 类型
- `QKeySequence(KeyboardModifier)` 报错：只接受 `(KeyboardModifier, Key)` 两个独立参数 或 `(QKeyCombination)` 或 `(int)`

```
QKeySequence(mod, key): ', R'              ❌ 修饰符丢失！
```

### 修复
```python

# 构造 QKeySequence 并发射

seq = QKeySequence(kc)
```


### 教训（重要！PySide6 6.x 通用经验）
1. **`Qt.KeyboardModifier` 是 `Flag` 不是 `IntFlag`**：不要 `int(Qt.ControlModifier)`，会报 `'KeyboardModifier' object is not a number`
2. **`Qt.Key` 是 `IntEnum`**：可以直接 `int(Qt.Key_R)` 或 `Qt.Key(int_value)`
3. **`QKeySequence` 不接受单个位运算结果**：必须用 `QKeyCombination(mod, key)` 显式组合，或直接 `QKeySequence(mod, key)`（但这个**会把修饰符丢了**，输出 ", R"）
4. **QKeyCombination 才是正确入口**：`QKeySequence(QKeyCombination(event.modifiers(), Qt.Key(event.key())))` 输出 "Ctrl+L"
5. **PySide6 与 PyQt5 在 enum 类型上差异显著**：PyQt5 时代 `QKeySequence(mod | key)` 工作正常（位运算 + int 接受）；PySide6 6.x 严格区分 Flag 和 IntEnum，必须用新 API

## 21:48：SpinBox 滚轮误触防护（用户反馈）

### 用户反馈
> 像设置以及配置的页面，鼠标滚轮划过某些数字的时候，它们会自己改动，这样很容易误触，怎么避免？

### 根因
`SpinBox` 默认重写 `wheelEvent`，鼠标悬停在上面滚动页面时数值自动增减。

### 修复
新增 `components/widgets.py` 共享控件模块，定义 `NoScrollSpinBox`：

```python
from PySide6.QtGui import QWheelEvent
from qfluentwidgets import SpinBox

class NoScrollSpinBox(SpinBox):
    """SpinBox 子类：只有获得焦点时才响应滚轮（避免页面滚动时误触）。"""
    def wheelEvent(self, event: QWheelEvent):
        if self.hasFocus():
            super().wheelEvent(event)
        else:
            event.ignore()
```

**行为**：
- 鼠标滚轮划过未聚焦的 NoScrollSpinBox → 值不变
- 点击 SpinBox 获取焦点后再滚轮 → 正常增减（和原版一致）

### 涉及页面（4 个）

| 文件 | SpinBox 数量 | 修复 |
|------|------------|------|
| `pages/settings.py` | 10 个 | 全部换 NoScrollSpinBox |
| `pages/config.py` | 1 个 | 换 NoScrollSpinBox |
| `pages/upgrade.py` | 2 个 | 换 NoScrollSpinBox |
| `pages/world.py` | 0 个（仅 import） | 删除多余 import |

### 架构改进：提取共享控件
之前三个文件各自定义了同名 `NoScrollSpinBox` 类（DRY 违反），现在统一到 `components/widgets.py`：

2. **`load()` 白名单过滤**：`load()` 只迭代 `DEFAULT_CONFIG` 的键来加载 JSON 内容，`window_geometry` 不在 DEFAULT_CONFIG 中 → 即使 JSON 文件里写入了也读不到

**2. `load()` 合并非标准键**

```python
# 用 schema 校验后的值覆盖标准字段
for k in DEFAULT_CONFIG:
    raw = loaded.get(k, DEFAULT_CONFIG[k])
    config[k] = _validate_value(k, raw)
# v3.02.01: 合并不在 DEFAULT_CONFIG 但 save 会写出的非标准键
```

`_validate_value` 检查 SCHEMA 的 key 时强制 `isinstance(value, (int, float))` → base64 字符串直接被打回默认值 `""`。

## 22:12：窗口恢复彻底修复 + 启动加速（用户反馈 2 项）

### 用户反馈
> 下次启动时恢复窗口大小还是不生效？拖动了之后，直接保存进配置文件。下次启动时直接读配置文件就行了。然后想办法优化一下启动速度。

### 窗口恢复：根因（第 3 次修复）
之前的修复仅改 save/load 白名单，但对 **时机** 仍不对：
- `_restore_window_state()` 在 `BDSFluentWindow.__init__` 中调用
- 此时 `window.show()` 还没调用
- `QMainWindow.restoreGeometry()` 在 window system 未 attach 时不生效（FluentWindow 的 super().__init__ 可能做了默认 resize 覆盖）

**修复1：把恢复移到 `showEvent`（等 window system 就绪）**
```python
def showEvent(self, event):
    super().showEvent(event)
    if not self._geom_restored:
        self._geom_restored = True
        self._restore_window_state()
```

**修复2：`_save_geometry` 同时保存 width/height（可靠 fallback）**
```python
config_mgr.set("window_geometry", geom_b64)
config_mgr.set("window_width", self.width())    # ← 冗余，但 100% 可靠
config_mgr.set("window_height", self.height())
```

**修复3：`_restore_window_state` 两层降级**
```python
# 优先：restoreGeometry（含 maximized + 位置）
if restoreGeometry(Base64 QByteArray):
    return
# 降级：resize(width, height) — 永远生效
self.resize(w, h)
```

### 验证
```
before show: QSize(800, 600)     ← FluentWindow 默认尺寸
after show:  QSize(1400, 827)    ← restoreGeometry 成功（height 修正为屏幕限制）
✅ 窗口恢复在 showEvent 时机正确生效
```

### 启动加速：闪屏动画优化

**1. 缩短每帧 sleep**：`0.016s → 0.008s`（动画仍平滑，但快一倍）

**2. 缩短各步 duration**：

| 步骤 | 之前 | 之后 |
|------|------|------|
| 错误处理 → 10% | 150ms | 60ms |
| 配置加载 → 25% | 200ms | 60ms |
| 字体设置 → 35% | 150ms | 50ms |
| 主窗口 → 45% | 150ms | 50ms |
| 主窗口 → 80% | 300ms | 100ms |
| 主题 → 95% | 200ms | 60ms |
| 完成 → 100% | 200ms | 60ms |
| **总睡眠** | **1350ms** | **440ms** |

**节省 ~0.9 秒**。加上 sleep 减半的效果，总启动动画从 ~1.4s → ~0.6s。

> 说明：BDSFluentWindow 构造本身 ~1.5s（QFluentWidgets + Qt 布局），这部分是 C++ 运行时开销，无法通过 Python 侧优化。

### 教训（通用）
1. **`restoreGeometry` 必须在 `show()` 之后调用**：在 window.show() 之前 window system 未 attach，QMainWindow 内部的 geometry 管理处于未就绪状态
2. **`showEvent` 是窗口状态恢复的最佳 Hook 点**：首次 show 时一次性恢复，避免每次 switchTo/activate 重复恢复
3. **config 多路保存是可靠的降级方案**：同时存 window_geometry（base64，含最大化）+ width/height（单值，纯 fallback），一个不工作另一个顶上
4. **闪屏进度条的意义是视觉反馈而非精确进度**：别用精确进度条浪费用户时间——用户要的是「快」不是「看起来在动」
