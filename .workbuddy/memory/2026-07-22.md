## v3.1.0 → v3.1.1 热修复（用户运行时报错）

### 错误
运行时 `dashboard.py:306` 每秒报一次：
```
AttributeError: 'NoneType' object has no attribute 'set_data'
  at update_stats → _set("cpu", ...) → getattr(self, "_cpu_curve").set_data(value, hist)
```

### 根因
`pages/dashboard.py` 的 `ResourceCard.__init__` 在调用 `_build()`（已通过 setattr 创建 `_cpu_curve / _mem_curve / _disk_curve`）之后，紧接着 3 行把它们又赋值为 None。这是 v3.1 重写 dashboard.py 时遗留的复制粘贴 bug。`monitor.stats_updated` 每秒触发 `update_stats → _set → getattr(self, "_cpu_curve")` 拿到 None。

### 修复
- 删掉 3 行 None 赋值，加注释禁止再覆盖
- `_set` 改成健壮版：val/bar/curve 任意为 None 时优雅跳过，monitor=None 也不崩

### 教训
- `__init__` 中只要有子部件在 `_build()` 里通过 setattr 动态创建，就不要在 `_build()` 之后再赋同名属性为 None
- 这类 bug 单测很难发现（_build 正常 = 构造无错），只有运行到 update_stats 才会爆
- 防御性编程：动态属性读取用 `getattr(..., None)`，不要相信属性一定存在

## 升级页获取策略：GitHub 重试 → 最后才嗅探（用户要求）

### 改前问题
- 用户点"浏览可用版本" → 1 次 GitHub 失败 → **立即**自动启动 HEAD 嗅探（106 秒）
- 没有重试，可能只是网络抖动就触发大规模嗅探

### 改后策略
1. **优先 GitHub**：用户触发后清旧表 → 启动 `GithubFetcher`
2. **失败重试 3 次**：指数退避 1s → 2s → 4s（`GITHUB_BACKOFF_BASE = 2`）
3. **状态栏显示**：「⚠️ GitHub 拉取失败，2s 后重试（2/3）」
4. **全部失败后**：把"停止"按钮变为「启用 HEAD 嗅探」让用户决定
   - 状态栏：「❌ GitHub 失败 3 次 — 可点停止按钮启用 HEAD 嗅探（最后手段，65+ 请求）」
5. **HEAD 嗅探成为最后手段**：用户主动启用，而非自动 fallback
6. **后台静默自动刷新** 也用同样的 3 次重试，但失败后只保留缓存（不打扰）

### 关键类属性
- `GITHUB_MAX_RETRIES = 3`
- `GITHUB_BACKOFF_BASE = 2`（秒）
- `self._pending_head_scan = False` 标记「等待用户决定是否启用 HEAD」

### 验证（5 场景全过）
- 3 次失败 → pending=True，按钮='启用 HEAD 嗅探' ✅
- 成功 → 更新表 ✅
- 静默失败 → 保留缓存，无 UI 干扰 ✅
- Backoff 序列：1s/2s/4s ✅

```python
    """把 (major, minor, patch) 元组格式化为 x.xx.xx 字符串。"""
    return f"{major}.{minor:02d}.{patch:02d}"
```
